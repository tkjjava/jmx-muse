# 断线续传活网取证与"重连不可证明连续性"收尾

## 结论

断线后重连机制本身有效：新订阅建立、带游标 resume、重放重复事件被本地去重、
没有重复正文。但两次活网探针都显示：**断线窗口内产生的事件没有被补发**，
重连后只从尾部继续；回合最终以普通 `agent.status:online` 收尾。正文长度远低于
同提示词的无断线基线（456 字符），因此"重连后收尾"不能当作完整回答。

修复：客户端在回合中重连时标记 `_turn_resumed`；引擎对这类回合只接受权威
`delta.message_done` 作为完成证据，普通客户端终态一律报"连续性无法确认"。

新增 1 条引擎契约回归（并把旧的"重连后普通收尾即完成"契约改写为两条：权威
完成可成功、普通收尾必须失败），完整套件 **1888 passed**。

## 探针证据（脱敏，不含正文/账号/令牌）

同一提示词（约 400 字中文说明），三种运行：

| 观测 | 基线（不断线） | 探针 A | 探针 B |
|---|---:|---:|---:|
| 总事件 | 47 | 19 | 15 |
| 正文段数 | 35 | 5 | 2 |
| 正文长度 | **456** | **66** | **28** |
| 重连次数 | 0 | 2 | 1 |
| 断线前最后 seq | — | 796（resume 游标） | 880 |
| 重连后首条已收 seq | — | — | **922** |
| 重连后正文段数 | — | 3 | 0 |
| 终态 | `agent.status:online` | `agent.status:online` | `agent.status:online` |
| 权威 `message_done` | 无 | 无 | 无 |
| 重复正文哈希 | 0 | 0 | 0 |
| 耗时 | 9.234s | 27.179s | 17.907s |

探针 B 的断线前最后 seq=880，重连后第一条已收事件是 922、终态 923：
881–921 从未到达。探针 A 同样在重连后只收到少量尾部正文。两次相连的
重连都被本地 de-dup 挡住重复事件，没有出现重复正文。

基线还证明 **seq 在无断线时也不连续**（47 个事件里存在一次 255 跳变），
所以不能用"seq 缺口"判断丢没丢事件，也不能据此自动补发。

## 修复内容

| 位置 | 行为 |
|---|---|
| `protocol_client.read_stream` | 每回合重置 `_turn_resumed=False`；回合中（已发消息后）重连成功即置 True |
| `protocol_engine._run`（聊天） | 完成依赖客户端终态时，若 `_turn_resumed` 且终态原因不是 `delta.message_done`，抛"连续性无法确认"，不产出 `done` |
| 已有 `delta.message_done` 路径 | 不变：权威完成事件仍可直接成功（重放重复正文继续按固定 floor 裁掉） |

生成路径无需改动：它本来就只认 `delta.message_done` 后的成品与宽限，不依赖
普通状态收尾。

## 可复现

```powershell
python tools/protocol_resume_probe.py --drop-after 2 --timeout 150
python -m pytest tests/test_protocol_resume.py -q -p no:cacheprovider
```

工具只读账号库，输出游标/seq/段数/是否权威完成的 JSON，不打印正文与凭据。
它会真实消耗一次约 400 字回答的额度并主动断线一次，只用于自有/已授权账号。

## 恢复层（opt-in，默认关闭）

既然 live 补发不可靠，唯一的恢复来源是已提交历史。`ProtocolEngine` 新增
`history_recovery: bool = False` 开关：**只有显式打开才生效**，当前 app 接线
仍保持关闭，直到 `chat.history` 响应形状被活网确认。

打开后，重连回合以普通状态收尾时按以下顺序判定：

| 检查 | 失败结果 |
|---|---|
| 客户端支持 `chat_history()` | 保留"连续性无法确认"错误 |
| 历史页最后一条 assistant 正文非空 | 同上 |
| 已收正文是它的**严格前缀**（`full.startswith(partial)` 且更长） | 同上 |
| 历史页 `newest_seq` 不早于 live 游标 `_last_seen_seq` | 同上 |
| 历史请求异常（任何异常） | 同上，不掩盖原错误 |

通过后把 `done` 文本替换为完整正文；`stream_chat` 仍先按原样吐已收到的
delta，`collect_chat` 改为在 `done` 存在时采用其文本（常态两者一致）。

7 条回归覆盖：正例、默认关闭不发历史请求、非前缀拒绝、等长拒绝、陈旧提交
拒绝、历史请求失败回退、`stream_chat` 的 delta+完整 `done` 组合。

**限制**：恢复只针对主会话（未传 `session_id`，线程回合仍会报不完整）；
`chat.history` 的真实字段仍未活网确认，所以默认值必须保持关闭。

## 尚未证明

探针只有两次，不能排除服务端在某些条件下会补发；`after_stream_seq` 的严格
大于/包含语义仍未确定。线程会话、跨设备取消与断线组合未验证。本报告只声明：
在这两次观测中，断线窗口事件没有补发，因此本地不得把"重连后普通收尾"当成功。
