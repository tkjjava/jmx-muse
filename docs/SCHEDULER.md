# 可回退的账号健康调度

## 启用与回退

| MUSE_SCHEDULER | 自动派单顺序 | 额外上游请求 |
|---|---|---|
| legacy（默认） | 原有轮转 | 无 |
| shadow | 原有轮转，同时计算评分首选并统计差异 | 无 |
| score | TopK 加权随机，保留其余候选作后备 | 无 |

在服务环境中设置 `MUSE_SCHEDULER=shadow`，重启后检查 `/healthz.scheduler_mode`。
观察管理端 `/admin/observability` 中 `scheduler_shadow_selections` 和
`scheduler_shadow_disagreements`；后者统计排序首位差异，不是性能提升或错误计数。
确认部署适用后可设置 `score`，回退设置 `legacy`。未知取值退回 `legacy`。
本轮未修改运行中服务的配置或重启服务。

## 单次派单探针预算

`MUSE_DISPATCH_MAX_ATTEMPTS=0` 默认不设限，保持旧行为；正整数限制单次 dispatch
最多探测多少个不同的空闲账号，上限 128。非法/负数退回 0，超过上限截为 128。
预算与调度模式独立，legacy/shadow/score 均生效；点名账号最多尝试该账号一次。

忙号不耗预算、同一账号不重复尝试。单账号的协议→浏览器回退仍属同一次账号尝试，
不把内部网络调用次数伪称为账号数。它不限制数据库扫描，也不代替网络连接超时。

达到上限且仍存在未尝试的空闲候选时返回 `dispatch_budget_exhausted`；聊天接口将其
映射为 HTTP 503 / server_error。全部候选已经尝试失败仍返回原 all_accounts_failed；
全部忙仍走原 429。未尝试账号不改状态、不记健康失败、不占锁。

`/healthz.dispatch_max_attempts` 展示生效上限；管理端观测计数：
`scheduler_account_attempts` 为实际账号尝试数，`scheduler_probe_budget_exhausted` 为预算耗尽次数。
从 0 切到正整数会减少单次换号范围，可能需要客户端重试。不要将它当成延迟保证。

## 实际使用的反馈

`pool.dispatch()` 对自动派单候选读取进程内快照：

- 当前账号锁占用率（单账号容量仍为 1）；
- 完整请求的成功/失败 EWMA，alpha=0.3；
- 从开始生成到首个有效 content/reasoning/media 输出的延迟 EWMA。

延迟不包括连接建立，不是整个 HTTP 请求的端到端 TTFT。没有样品或同值样品取中性
0.5。字符串、事件、非流式收集共用回报路径，兼容事件适配器不重复记样。
驱动建立失败记录失败；仅建立成功不记录请求成功，以免稀释后续生成失败。
生成以独立能力桶记录成功/失败，不把视频总耗时冒充聊天首输出延迟。

评分器还支持优先级、配额余量等输入，但本次接线没有可靠数据源，保持中性默认，
不从未知配额推算百分比。自动评分不会越过 store 的状态/探针闸门。

## 锁、恢复与取消

点名账号绕过评分，仍须通过现有可派单闸门与账号锁。全忙仍抛 AllAccountsBusy；
驱动失败依次尝试后备账号，锁在失败、异常、取消时释放，成功时交调用方持有。

错误率是降权项，不因历史高错误率永久剔除候选：接线显式使用 max_error_rate=1。
这样恢复账号仍可再次获得请求并用成功样品降低错误率。无效的非有限错误率不入选。
客户端取消、提前关闭输出生成器不计上游失败；真实抛出的请求异常计失败。
现有协议驱动若将截断转换成正常完成，本层无法凭空识别其终止原因，不宣称覆盖该情况。

健康数据只存内存，不含 cookie、提示词或密钥；最多 1024 个账号/能力组合，闲置
30 分钟过期。删号回收状态，重启清空。不引入数据库迁移、Redis 或后台探测。

## 验证与后续边界

派单级回归覆盖真实 SQLite store、真实账号锁、shadow 零额外连接、点名绕过、
全忙、失败换号、流式单次记样、异常、取消、TTL、容量与能力隔离。
数值回归覆盖空权重、同值/缺失 TTFT、NaN/Infinity、超大有限值与轮盘数值稳定性。
本轮使用离线驱动验证行为，没有把它称为活网性能验收。

粘性会话、跨租户 session 标识、数据库复核预算、可靠配额余量接入不在本次变更中。
这些需要明确会话归属和指标来源，不能仅添加一个字段便宣称已完成。
